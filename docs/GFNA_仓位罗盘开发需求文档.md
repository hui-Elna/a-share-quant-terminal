## 1. 背景与目标

### 1.1 背景

现有量化选股产品以个股推荐为核心，存在三个结构性问题：

1. 选择域过大，5000 只个股中选 3 只，样本外衰减明显；
2. 个股特有风险（退市、造假、一字跌停、流动性枯竭）无法通过选股逻辑消除；
3. 产品承诺“选出好股票”，属于结果承诺，一次亏损就会击穿信任。

产品方向调整为“面向散户的量化选板块”，用 ETF 承接板块，降低个股特有风险。但仅把“选股”换成“选板块”，仍然是收益承诺。因此本产品的定位进一步收敛为：

> **不做收益推荐，只做风险预算与决策约束。**

### 1.2 产品一句话

每天盘后告诉用户四件事：**今天做不做、最多做多大、往哪个方向做、什么条件下撤**；不告诉用户“买哪只、能赚多少”。

### 1.3 目标用户

- 有 A 股证券账户，可交易场内 ETF；
- 单笔可投入资金 5–50 万元；
- 每天愿意投入不超过 10 分钟；
- 不具备财报分析、产业链验证和编程能力；
- 能接受“多数时间不操作”，而不是追求每天交易。

### 1.4 成功判据

> 如果产品在样本外、扣除全部摩擦成本后，能让用户的**最大回撤与错误交易次数显著下降**，而**不承诺**收益率提升，则产品成立；如果必须靠“这个月赚了多少”来卖，则它是伪需求。

该判据同时约束产品、运营与销售话术。

### 1.5 非目标（P0 明确不做）

| 不做 | 原因 |
|---|---|
| 个股推荐 | 与产品定位冲突，且合规风险最高 |
| 单一买卖结论 | 无法承诺收益，且使用户放弃判断 |
| 盘中实时信号 | 数据与执行链路不支持，且放大追涨杀跌 |
| 自动交易 / 代客操作 | 牌照与合规红线 |
| 收益承诺、历史收益营销 | 违反成功判据 |
| 概念板块（MVP） | 重叠度高、ETF 映射覆盖率低，留待 P1 评估 |

## 3. 信息架构与路由

### 3.1 一级导航

| Tab | 路由 | 职责 |
|---|---|---|
| 今日决策 | `/compass/today` | 当日结论、预算、仪表盘、候选池、T+1 校验 |
| 情景卡 | `/compass/scenarios` | 6 张 if-then 规则与触发状态 |
| 复盘验证 | `/compass/review` | 回撤、错误次数、避损、失效记录 |
| 规则与边界 | `/compass/rules` | 权限、承诺、非目标、判据、版本 |

### 3.2 入口

1. Web 主入口，默认进入 `/compass/today`。
2. 企业微信推送深链，直接进入当日决策卡，锚点定位到校验条。
3. 付费转化页，进入 `/compass/rules` 的权限表。
4. 历史卡片分享链接，进入只读详情，禁止 T+1 操作。

### 3.3 路由边界

- 未登录访问 `/compass/today`：展示脱敏示例 + 登录引导，不返回真实候选 ETF。
- 订阅过期：页面可读，付费字段脱敏，顶部显示“已到期，查看权益”。
- 非交易日：`/compass/today` 展示最近一张决策卡，并标注“历史决策卡 / 非交易日”。

## 4. 全局业务规则

### 4.1 时间与交易日

| 项 | 规则 |
|---|---|
| 时区 | 全部使用 `Asia/Shanghai`，接口时间戳为 ISO-8601 含 `+08:00` |
| 交易日 | 以 `trade_calendar` 为准，禁止用自然日推断 |
| 决策卡生成 | 盘后数据采集与入库校验通过后自动触发；失败由 30 分钟巡检续跑 |
| 推送 | 决策卡校验通过后由盘后串行链路推送；进程离线时启动补跑后续推 |
| T+1 校验 | 次一交易日 09:35:00 启动，09:35:30 前出结果 |
| 10:00 复核 | 次一交易日 10:00，未处理项自动按规则收口 |
| 非交易日 | 不生成新卡、不推送、不校验；展示最近一张卡 |

### 4.2 市场状态：读取，不重算

市场状态来自现有五态状态机（`risk_off / trend_up / bottoming / repair_up / pull_down`），已包含 3 日迟滞、最短驻留 5 日、`risk_off` 立即切换等规则。**本产品不得重新计算状态，也不得叠加第二层迟滞。**

#### 4.2.1 五态聚合为三档预算

| 产品档位 | 内部五态 | 总执行仓位上限 |
|---|---|---|
| 进攻 | `trend_up` | 80% |
| 震荡 | `repair_up` | 40% |
| 防守 | `bottoming`、`pull_down`、`risk_off` | 10% |

说明：

- `bottoming` 归入防守是**保守选择**，目的是避免在底部反复试错；如未来要单独提高底部预算，必须作为新参数版本评审，不得在 MVP 中暗改。
- 产品档位只影响预算上限，不改变状态机输出，也不影响其他看板。
- 状态切换当日，预算上限立即按新状态生效；决策卡是 T 日收盘快照，生成后当日不再变更。

#### 4.2.2 状态缺失与低把握度

- 状态缺失、状态为 `unknown`、或 `confidence=insufficient`：**不生成决策卡**，返回 `DATA_NOT_READY`，推送“数据未就绪”通知。
- `confidence < 45`：MVP 仅展示“低把握度”标签，不调整预算；P1 再引入“低把握度降档”规则（需回测校准）。
- 温度分只用于展示与情景卡证据，**不得**用温度阈值反推市场状态。

#### 4.2.3 温度分区（与 V7 一致）

| 分数 | 档位 | 仪表盘文案 |
|---|---|---|
| 0–19 | 冰点 | 冰点 0–19 |
| 20–39 | 清冷 | 清冷 20–39 |
| 40–59 | 平稳 | 平稳 40–59 |
| 60–79 | 温热 | 温热 60–79 |
| 80–100 | 沸腾 | 沸腾 80–100 |

### 4.3 候选池流水线

每个交易日 T 收盘后，按以下顺序执行，任一阶段失败即停止并记录原因。

#### 4.3.1 阶段 0：评估集

纳入：

- `sector_type = industry`（MVP 仅行业板块）；
- 当日 `sector_score` 存在；
- `member_count >= 5`；
- 成分归属为 SCD2 当日有效版本，且 `is_partial = false`；
- 核心技术分、情绪分均非空；
- 资金流聚合可用。

排除并记录原因：

| 原因码 | 条件 |
|---|---|
| `INSUFFICIENT_MEMBERS` | 有效成分股少于 5 只 |
| `PARTIAL_MEMBERSHIP` | 成分数据标记为 partial |
| `MISSING_CORE_SCORE` | 技术分或情绪分为空 |
| `MONEYFLOW_MISSING` | 板块资金流聚合不可用 |
| `STALE_SECTOR_DATA` | 板块日线非最新交易日 |

新闻分缺失不排除，但标记 `news_missing=true`，综合分按中性 5.0 计算。

#### 4.3.2 阶段 1：初筛池（相对门槛）

按综合分降序取前 8 名，形成初筛池。

综合分口径与现有实现一致：

```
composite = technical × 0.40 + sentiment × 0.35 + news × 0.25
```

排序稳定规则（必须确定性）：

1. 综合分降序；
2. 技术分降序；
3. 情绪分降序；
4. `sector_code` 字典序升序。

#### 4.3.3 五道门槛（按顺序判定，记录首个失败原因）

**G1 绝对门槛**

- `composite >= 6.5`
- `technical >= 6.0`
- `sentiment >= 5.5`

**G2 连续性**

- 该板块在 T 日与上一交易日均在初筛池内；
- 上一交易日无评分或不在初筛池，均判定失败；
- 不得用自然日替代交易日。

**G3 广度一致性**

- 有效成分股上涨占比 `>= 55%`；
- 板块主力净流入 `> 0`；
- 上涨占比分母只统计当日有有效涨跌幅、且未停牌的成分股；
- 资金流缺失直接判定失败，不用 0 代替。

**G4 相关性去重**

- 取板块指数最近 60 个交易日日收益率；
- 两两 Pearson 相关系数 `> 0.85` 视为高相关；
- 高相关组内只保留综合分最高者；同分时保留 ETF 日均成交额更高者；
- 重叠交易日少于 40 天时，`correlation_check = skipped`，允许通过但打标提示。

**G5 ETF 可执行性**

- 存在唯一 `is_primary = true` 的 ETF 映射；
- ETF 已上市、未退市、T 日未停牌；
- 基金规模 `>= 2 亿元`；
- 20 日日均成交额 `>= 3000 万元`；
- T 日收盘绝对溢价率 `<= 1.5%`。

失败原因码：

| 原因码 | 条件 |
|---|---|
| `NO_TRADABLE_ETF` | 无主映射 |
| `MULTIPLE_PRIMARY_ETF` | 主映射不唯一，数据质量告警 |
| `ETF_SUSPENDED` | T 日停牌 |
| `ETF_TOO_SMALL` | 规模不足 |
| `ETF_ILLIQUID` | 日均成交不足 |
| `ETF_PREMIUM_TOO_HIGH` | 溢价超限 |

#### 4.3.4 阶段 2：输出

- 通过全部五道门槛的板块，按综合分取前 3；
- 不足 3 个时**不补位**，输出实际数量；
- 0 个时进入空仓状态，给出空仓原因码；
- 输出顺序即展示顺序，不得前端重排。

#### 4.3.5 单板块上限

```
raw = min(0.20, exec_cap × 0.40)
per_sector_cap = floor(raw / 0.05) × 0.05
```

- `exec_cap = 0` 时，`per_sector_cap = 0`；
- 例：`exec_cap = 40%` → `raw = 16%` → `per_sector_cap = 15%`；
- 例：`exec_cap = 80%` → `raw = 20%` → `per_sector_cap = 20%`；
- 展示为整数百分比，禁用小数。

#### 4.3.6 空仓原因

空仓不是单一原因，接口返回原因数组，前端按优先级展示前 3 条：

| 优先级 | 原因码 | 文案 |
|---|---|---|
| 1 | `REGIME_DEFENSE` | 市场状态为防守，预算上限仅 10% |
| 2 | `NO_ABSOLUTE_PASS` | 0 个板块通过绝对门槛 |
| 3 | `CROWDING_REVERSAL` | N 个板块情绪分位 > 90 且资金流转负 |
| 4 | `BREADTH_BREAKDOWN` | 板块内跌破 20 日线成分占比 > 60% |
| 5 | `NO_TRADABLE_ETF` | 通过门槛的板块无合格 ETF |
| 6 | `DATA_INCOMPLETE` | 核心数据缺失，无法形成结论 |

### 4.4 情景卡求值

#### 4.4.1 六张卡

| ID | 名称 | 条件 | 动作 | 失效条件 |
|---|---|---|---|---|
| SC-01 | 空仓优先 | 市场状态 ∈ {`pull_down`,`risk_off`} 且候选池为空 | 执行仓位归零，不新开仓、不补仓 | 状态回到 `repair_up` 及以上，且至少 1 个板块通过门槛 |
| SC-02 | 单板块上限 | 候选池 ≥ 2 个 | 单板块 ≤ `floor(min(20%, 总预算×40%)/5%)×5%` | 候选池只剩 1 个时，上限不变 |
| SC-03 | 停止加仓 | 情绪分位 ≥ 90 且主力净流转负 | 停止加仓，不新开仓；已有仓位不因情绪单独卖出 | 分位回落至 80 以下，且资金流转正 2 日 |
| SC-04 | 延迟执行 | T+1 开盘偏离绝对值 > 2% 或 ETF 停牌 | 延迟至 10:00 复核；仍超阈值则放弃本次 | 偏离回到 2% 以内 |
| SC-05 | 退出 | 板块指数收盘跌破 20 日线，或 60% 成分股跌破 | 清仓该方向，不摊平 | 指数重新站上 20 日线，且广度恢复 55% 以上 |
| SC-06 | 失效降级 | 滚动 60 日超额转负 | 全系统降级为“仅供参考”，暂停推送，公开失效报告 | 连续 20 日超额回正且通过样本外复核 |

#### 4.4.2 状态

| 状态 | 含义 | 展示 |
|---|---|---|
| `STANDING` | 长期生效的约束（SC-02） | 生效中 |
| `ARMED` | 今日未触发 | 未触发 |
| `TRIGGERED` | 今日触发，必须记录证据 | 已触发 |
| `EXPIRED` | 失效条件满足 | 已失效 |
| `MUTED` | 用户关闭推送，但仍记录（P1） | 已静音 |

#### 4.4.3 冲突优先级

从高到低：

1. `SC-06` 系统降级：停止生成新卡；
2. `SC-01` 空仓：执行仓位归零；
3. `SC-05` 退出：清仓该方向；
4. `SC-03` 停止加仓：禁止新增；
5. `SC-04` 延迟执行：控制执行时点；
6. `SC-02` 单板块上限：分配约束。

**硬性要求**：优先级只影响动作，不影响记录；所有触发都必须写入 `fact_scenario_trigger`，不得因被高优先级覆盖而丢弃。

#### 4.4.4 求值时点

- 盘后决策卡生成后求值一次；
- T+1 09:35 只重新求值 SC-04，其余卡片状态不变；
- 10:00 复核再次求值 SC-04；
- 收盘后回填 SC-05 与纸面组合结果。

### 4.5 数值精度与取整

| 字段 | 精度 | 取整方式 |
|---|---|---|
| 评分（技术/情绪/新闻/综合） | 1 位小数 | 四舍五入 |
| 情绪分位 | 整数 | 四舍五入 |
| 仓位上限 | 整数百分比 | 向下取 5% 步长 |
| 开盘偏离 | 2 位小数 | 四舍五入 |
| 基金规模 | 亿元，1 位小数 | 四舍五入 |
| 资金流 | 亿元，1 位小数 | 四舍五入 |
| 相关系数 | 2 位小数 | 四舍五入，判定用原始值 |

其他要求：

- 禁止输出 `-0.0`，统一归零；
- 前端不得二次取整，展示值与接口值一致；
- 百分比字段接口返回数值（如 `40` 表示 40%），不返回带 `%` 的字符串。

### 4.6 数据新鲜度与失败策略

决策卡依赖的关键数据集：

| 数据集 | 关键性 | 缺失后果 |
|---|---|---|
| `trade_calendar` | 关键 | 不生成卡片 |
| `sector_daily` | 关键 | 不生成卡片 |
| `sector_members` | 关键 | 不生成卡片 |
| `moneyflow` | 关键 | 不生成卡片 |
| `margin` | 关键（情绪子项） | 不生成卡片 |
| `market_temperature_daily` | 关键 | 不生成卡片 |
| `etf_daily` | 关键 | 不生成卡片 |
| `etf_sector_map` | 关键 | 不生成卡片 |
| `news` | 非关键 | 新闻分按 5.0，标记 `news_missing` |

失败策略：

- 任一关键数据集 `status != ok`：卡片状态 `INCOMPLETE`，不推送，接口返回 `409 DATA_NOT_READY` 或 `DATA_QUALITY`；
- 关键数据集 `status = stale` 且超过 1 个交易日：同上；
- 非关键缺失：正常生成，但在决策卡与复盘页显示“新闻分缺失”标记；
- 禁止用 0、均值或其他板块数据填补缺失值。

### 4.7 版本、幂等与不可变

- 规则版本：`COMPASS_RULE_VERSION`，每次参数变更必须升级；
- 决策卡携带 `rule_version` 与 `signal_version`；
- 同一交易日同一版本只允许一张有效卡；新版本生成新卡，旧卡标记 `superseded`，不可覆写；
- 生成接口、推送接口、T+1 操作接口都必须支持幂等键；
- 历史卡片、触发记录、失效记录只追加，不提供删除接口。

## 5. 模块需求

### 5.1 今日决策卡（P0）

#### 5.1.1 目标

让用户在 10 秒内知道“今天做不做、最多做多大”，并能一键查看推导依据。

#### 5.1.2 页面元素

| 元素 | 数据字段 | 说明 |
|---|---|---|
| 日期与阶段 | `trade_date`、`session` | 如“2026-11-23 周一 · 09:40 盘前” |
| T+1 状态徽标 | `check_status` | 已校验 / 待处理 / 空仓免校验 |
| 执行仓位上限 | `exec_cap` | 大号数字；为 0 时显示“空仓” |
| 结论说明 | `cap_summary` | 一段话解释预算来源 |
| 预算条 | `market_cap`、`per_sector_cap` | 填充为市场层预算，刻度为单板块上限 |
| 市场状态 | `regime`、`temp_score` | 档位名 + 温度 |
| 迷你指标 | `output_count`、`per_sector_cap`、`idle_days` | 输出板块数、单板块上限、空仓天数 |
| 推导链按钮 | `derivation_id` | 打开抽屉 |

#### 5.1.3 交互逻辑

1. 进入页面：请求 `GET /api/v1/compass/today`。
2. 有卡片：渲染；数字使用 480ms 缓动，`prefers-reduced-motion` 下直接呈现。
3. 无卡片且当前交易日 16:30 前：显示“今日卡片生成中”，每 30 秒轮询，最多 20 次。
4. 无卡片且 16:30 后：显示失败态与“稍后重试”，禁止展示昨日卡片冒充今日。
5. 非交易日：展示最近一张卡，顶部标注“历史决策卡 / 非交易日”，隐藏 T+1 操作。
6. 点击“查看推导链”：抽屉从右侧滑入，内容由服务端返回，前端不得本地拼接。
7. 推导链步骤固定为 5 步：温度背景 → 状态机输出 → 预算上限 → 候选池结果 → 单板块上限与执行结论。

#### 5.1.4 边界条件

| 场景 | 期望行为 |
|---|---|
| `exec_cap = 0` | 大字显示“空仓”，不显示“0%”；说明中给出市场层预算与空仓原因 |
| 市场层 10% 但候选为 0 | 显示“空仓”，说明“市场层上限 10%，候选池为空，执行仓位 0%” |
| 卡片超过 1 个交易日 | 只读；隐藏 T+1 操作；顶部标注“历史卡片” |
| 推导链缺失 | 不渲染按钮，记录前端告警；不得用本地规则补齐 |
| 数字动画中切换状态 | 取消上一动画，以最新值为准 |
| 接口超时 | 展示最近缓存卡片 + 新鲜度徽标；无缓存则错误态 |
| 用户放大字体 | 布局不得溢出；大号数字允许换行 |

#### 5.1.5 验收

- 页面展示的 `exec_cap`、`market_cap`、`per_sector_cap` 与接口一致；
- 推导链最后一步与顶部结论一致；
- 空仓态不出现“0%”主视觉；
- 非交易日不出现可点击的 T+1 操作。

### 5.2 风险仪表盘（P0）

#### 5.2.1 目标

提供“状态描述”，不提供方向判断。用户看完应知道市场温度、哪些板块拥挤、是否存在资金流背离。

#### 5.2.2 元素

| 元素 | 数据 | 规则 |
|---|---|---|
| 温度条 | `temp_score` | 0–100，五等分，V7 文案 |
| 温度标记 | `temp_score` | 位于对应百分比，显示数值 |
| 情绪分位列表 | `sectors[].sentiment_percentile` | 默认展示输出板块；空仓时展示初筛池前 3 |
| 分位条 | 0–100 | ≥90 红色，其余墨色 |
| 标签 | `crowding_level` | 过热 / 偏热 / 正常 / 偏冷 / 样本不足 |
| 风险标记 | `flags[]` | 背离、拥挤、相关性去重、广度不足 |

#### 5.2.3 交互

- 默认静态展示，不要求悬浮提示；
- 点击板块行可以展开子分数（技术/情绪/新闻）与有效样本数（P1）；
- 空仓状态下，列表标题改为“观察板块”，避免用户误以为可买。

#### 5.2.4 边界

| 场景 | 期望行为 |
|---|---|
| 温度缺失 | 隐藏温度条，显示“温度数据不足”，不得显示 0 |
| 情绪分位样本 <60 | 显示“样本不足”，条形置灰；SC-03 判定为 false |
| 情绪分位恰好 90 | 判定为过热（`>= 90`） |
| 资金流缺失 | 不显示背离标记；该板块已被评估集排除 |
| 标记超过 3 条 | 按“背离 > 拥挤 > 相关性 > 广度”优先级取前 3 |
| 空仓且初筛池为空 | 列表显示“无可观察板块”，不伪造数据 |

### 5.3 候选池（P0）

#### 5.3.1 元素

表头：排名、板块、综合、技术、情绪、消息、情绪分位、对应 ETF、状态。

行展开后固定两栏：

- 可归因理由（3 条，来自 `reasons[]`）；
- 门槛校验（5 条，逐条显示通过值与阈值）。

底部：

- “未通过门槛 N 个”折叠区；
- 每行显示板块名、综合分、首个失败原因；
- 空仓时显示空状态，不显示表头。

#### 5.3.2 交互

- 点击行切换展开，允许同时展开多行；
- 切换交易日或市场状态演示时，展开状态重置；
- 键盘 Enter / Space 等价点击；
- 未通过门槛列表默认折叠，展开状态不持久化。

#### 5.3.3 边界

| 场景 | 期望行为 |
|---|---|
| 输出 0 个 | 空状态：大号 0 + “不是数据故障，是今天的结论” + 原因 + 空仓天数 |
| 输出 1–2 个 | 正常展示，底部注明“仅 N 个通过，不补位” |
| 通过门槛但 ETF 不合格 | 不进入输出；进入未通过列表，原因 `NO_TRADABLE_ETF` |
| 主映射不唯一 | 该板块排除，写数据质量告警，运营需人工修复映射 |
| 相关系数计算样本不足 | 允许输出，行内标注“相关性未校验” |
| 初筛池不足 8 个 | 按实际数量输出，不补位；页面提示“今日初筛不足” |
| ETF 溢价刚好 1.5% | 通过（`<= 1.5%`） |
| ETF 成交额刚好 3000 万 | 通过（`>= 3000 万`） |

### 5.4 情景卡（P0）

#### 5.4.1 元素

- 筛选：全部 / 已触发 / 待命；
- 卡片：ID、名称、条件（等宽字体）、状态、展开按钮；
- 展开内容：执行动作、失效条件、依据、最近触发时间；
- 触发证据：接口返回 `evidence`，前端可展开查看（P1）。

#### 5.4.2 交互

- 点击标题展开 / 收起，手风琴不互斥；
- 筛选切换后保持已展开卡片的展开状态（如仍在结果集中）；
- 从今日页“当前触发”点击进入时，自动切换到情景卡页并展开对应卡片；
- 触发状态每 60 秒轮询一次，页面隐藏时暂停。

#### 5.4.3 边界

| 场景 | 期望行为 |
|---|---|
| 同一板块同时触发 SC-03 与 SC-05 | 两条都记录；执行动作按优先级以 SC-05 为准 |
| SC-06 触发 | 顶部全局横幅提示“系统已降级”，所有卡片只读 |
| 免费用户 | SC-01、SC-03 可读；其余显示锁定态与升级入口，不返回正文 |
| 触发证据缺失 | 显示“已触发”，但不显示证据；记录后端告警 |
| 历史触发 | 只读，不允许修改状态 |

### 5.5 T+1 开盘校验（P0）

#### 5.5.1 目标

在用户执行前拦截“开盘跳空过大”的追高 / 恐慌行为。

#### 5.5.2 计算

```
open_gap = (open_price / prev_close - 1) × 100
```

- 阈值：`|open_gap| > 2.00%`；
- 恰好 2.00% 不触发；
- ETF 停牌直接触发 `SUSPENDED`；
- 开盘价取 09:30–09:35 的首个有效成交价；
- 开盘价缺失时，状态为 `DATA_NOT_READY`，不猜测。

#### 5.5.3 状态机

| 当前状态 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| `PENDING` | 09:35 任务启动 | `CHECKING` | 开始拉取开盘价 |
| `CHECKING` | 全部标的计算完成且无需延迟 | `PASS` | 展示“校验通过” |
| `CHECKING` | 任一标的超阈值 | `WARN` | 展示延迟条与操作按钮 |
| `CHECKING` | 任一标的停牌 | `SUSPENDED` | 禁止执行该标的 |
| `WARN` | 用户点击“延迟至 10:00” | `DELAYED` | 记录操作人和时间 |
| `WARN` | 用户点击“放弃本次” | `DROPPED` | 记录原因 |
| `DELAYED` | 10:00 复核仍在阈值内 | `PASS_AFTER_RECHECK` | 允许执行 |
| `DELAYED` | 10:00 复核仍超阈值 | `DROPPED_BY_RULE` | 自动放弃，可申诉 |
| `WARN` / `DELAYED` | 10:00 前无操作 | `EXPIRED` | 默认放弃，禁止补操作 |
| 任意 | 卡片超过 1 个交易日 | `CLOSED` | 只读，不再接受操作 |

#### 5.5.4 交互

- 校验条显示：状态标题、涉及标的、偏离值、建议动作；
- `WARN` 状态提供两个按钮：“延迟至 10:00”、“放弃本次”；
- 用户操作后，按钮消失，状态条变为已处理，并显示操作时间；
- 09:45 未处理，推送一次提醒；
- 10:00 自动收口，页面无需用户在线。

#### 5.5.5 边界

| 场景 | 期望行为 |
|---|---|
| T+1 为非交易日 | 顺延到下一交易日，文案改为“下一交易日 09:35” |
| 用户重复点击 | 幂等：返回首次操作结果，不新增记录 |
| 两个标的均超阈值 | 校验条分别列出，操作可逐项处理（P0 支持单标的操作） |
| 用户已线下执行后再点“放弃” | 允许，但记录 `user_override=true`，复盘计入错误次数 |
| 开盘价缺失 | `DATA_NOT_READY`，不自动放弃；09:50 重试一次 |
| 停牌后复牌 | 不自动恢复，需用户重新进入页面触发复核 |
| 卡片已过期 | 不显示操作按钮，仅展示历史结果 |

### 5.6 复盘验证（P0）

#### 5.6.1 指标定义

| 指标 | 公式 | 说明 |
|---|---|---|
| 最大回撤 | `min(NAV_t / max_{s<=t} NAV_s - 1)` | 日频收盘，窗口内最低点 |
| 错误交易次数 | 违反生效情景卡的交易笔数 | 如 SC-03 触发后仍加仓、SC-05 触发后未退出 |
| 空仓避损 | `-Σ(benchmark_return_t)`，仅空仓日 | 基准为中证 800，正数表示避开下跌 |
| 错过涨幅 | `Σ(max(benchmark_return_t, 0))`，仅空仓日 | 正数表示错过上涨 |
| 净避损 | 空仓避损 - 错过涨幅 | 可在说明中展示，不作为营销口径 |

**硬性要求**：页面不得展示策略收益率、年化收益、累计收益曲线。

#### 5.6.2 图表

- 两条最大回撤曲线：遵守规则、无约束；
- 横轴为交易日，纵轴为回撤百分比；
- 超过 260 个点时按周降采样，保留极值；
- 标注信号失效窗口，至少 1 条；
- 图例与注释必须说明“纸面组合、含摩擦成本”。

#### 5.6.3 失效记录

字段：日期、事件、影响、归因、修复版本、状态。

- 只追加，不删除；
- 管理员只能新增“更正说明”，不能修改原记录；
- 前端默认展示最近 12 个月，最多 50 条，支持导出 CSV（专业版）。

#### 5.6.4 边界

| 场景 | 期望行为 |
|---|---|
| 纸面组合不足 60 个交易日 | 不展示统计值，显示“样本不足” |
| 数据缺口 >3 个交易日 | 窗口标记 `partial`，图表断点，不得插值 |
| 失效记录为空 | 显示“暂无记录”，不得伪造“零失效” |
| 用户为免费版 | 只展示月度摘要与最近 3 条失效记录 |

### 5.7 规则与边界（P0）

- 静态内容，由 `compass_rules` 配置或 CMS 提供，带 `rules_version`；
- 不依赖行情接口，行情失败时仍必须可访问；
- 内容必须包含：权限矩阵、承诺、不做清单、共同判据、规则版本、数据截止时间；
- 合规免责声明缺失时，**阻断发布**；
- 页面不得放在付费墙后。

### 5.8 推送（P0）

| 项 | 规则 |
|---|---|
| 渠道 | 企业微信群机器人（MVP 唯一渠道） |
| 时点 | 交易日 17:00，生成失败则 17:10 重试一次 |
| 幂等键 | `card_id + channel + user_id` |
| 重试 | 3 次，间隔 5s / 15s / 45s |
| 失败 | 标记 `push_failed`，运营后台可见；不静默 |
| 免费版 | 仅摘要：状态、预算、1 个板块名称；不含 ETF 代码与情景卡 |
| 专业版 | 完整：预算、3 个板块、ETF、情绪分位、深链 |
| 空仓 | 推送“今日空仓”卡片，说明原因，不推“无数据” |
| 静默时段 | 21:00–08:00 不推送；延迟到次日 08:30，并标注“延迟” |

推送内容不得包含“推荐买入”“预期收益”“稳赚”等表述。

### 5.9 订阅与付费墙（P1）

- 权益以服务端 `subscription` 为准，前端仅做展示；
- 到期后 7 天宽限期，期间只读；
- 宽限期结束：付费字段脱敏，保留仪表盘与规则页；
- 支付确认中：显示“支付确认中”，不提前放行；
- 退款：按订阅条款执行，退款后立即降级；
- 所有脱敏字段在接口层处理，不能只靠 CSS 隐藏。

## 7. 接口需求

### 7.1 通用约定

- 前缀 `/api/v1`；
- 成功响应不包 `data` 壳；
- 错误响应沿用 V5 统一结构，禁止新增未登记错误码；
- 所有展示接口附带 `freshness`；
- 所有决策卡接口返回 `rule_version` 与 `signal_version`；
- 列表接口支持 `limit` / `offset`，默认 `limit=20`，最大 `100`。

## 9. 非功能需求

### 9.1 性能

|---|---|
| `GET /compass/today` p95 | ≤ 300ms（缓存命中） |

| 复盘页首屏 | ≤ 2s |

### 9.2 可用性

- 交易日 08:30–18:00 可用性 ≥ 99.5%；
- 生成任务失败自动重试，重试失败必须告警；
- 推送失败不影响页面访问；
- 单点故障不得导致历史卡片不可读。

### 9.3 可观测性

必须采集：

- 卡片生成成功率、耗时、失败原因；
- 各门槛淘汰数量分布；
- 空仓天数占比；
- 情景卡触发次数；
- T+1 校验触发率、延迟率、放弃率；
- 推送成功率、打开率；
- 免费转付费率、月流失率；
- 数据新鲜度异常次数。

### 9.4 安全与合规

- 管理员接口必须内网 + 密钥；
- 用户操作记录保留 5 年；
- 不采集身份证、银行卡、持仓明细等敏感信息；
- 页面与推送必须包含“不构成投资建议”；
- 禁止收益承诺、历史收益截图、稳赚话术；
- 付费前必须完成合规文本评审。

### 9.5 可访问性

- 键盘可完成全部操作；
- 颜色不是唯一状态标识；
- 支持 `prefers-reduced-motion`；
- 正文对比度 ≥ 4.5:1；
- 大字号下表格可横向滚动，不截断关键字段。
